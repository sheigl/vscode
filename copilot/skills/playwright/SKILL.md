# Playwright E2E Testing Skill

Run Playwright end-to-end system tests with screenshot capture and visual verification. Automatically detects environment capabilities and falls back to Docker when native installation is not available.

## What This Skill Does

1. Detects existing Playwright installation or project configuration
2. Installs Playwright natively OR sets up a Docker-based execution environment
3. Discovers and runs e2e test suites against the application under test
4. Captures screenshots on every test step, success, and failure
5. Reviews screenshots to visually verify UI correctness beyond pass/fail assertions

## Pre-Execution Requirements

Before running any tests, determine the execution environment:

```
1. Check for existing Playwright installation → 2a. Use native if available
   OR
2b. Attempt native install → 3a. Use native on success
    OR
3b. Fall back to Docker container execution
```

## Phase 1: Environment Detection

### Step 1: Detect Existing Setup

Check for an existing Playwright configuration in the workspace:

```bash
# Check for playwright config files
ls -la playwright.config.* 2>/dev/null || ls -la e2e/playwright.config.* 2>/dev/null || ls -la tests/e2e/playwright.config.* 2>/dev/null

# Check if @playwright/test is installed
npx playwright --version 2>/dev/null

# Check for existing test files
find . -name "*.spec.ts" -o -name "*.spec.js" -o -name "*.test.ts" 2>/dev/null | head -20

# Check package.json for playwright dependency
grep -i playwright package.json 2>/dev/null
```

### Step 2: Determine Application URL

The application under test must be running. Resolve the target URL:

1. Check `playwright.config.ts` (or `.js`) for `use.baseURL`
2. Check environment variables (`APP_URL`, `BASE_URL`, `E2E_BASE_URL`)
3. Check project documentation or `AGENTS.md` for startup instructions
4. If the app is not running, start it before proceeding

## Phase 2: Installation

### Path A: Native System Installation (Preferred)

Attempt native installation first. This provides best performance and debugging experience.

```bash
# Install Playwright test runner as dev dependency
npm install -D @playwright/test@latest

# Install browser binaries (chromium is default for e2e)
npx playwright install --with-deps chromium

# Verify installation
npx playwright --version
npx playwright show-report --help >/dev/null 2>&1 && echo "Playwright ready"
```

**If native install fails** due to missing system dependencies, OS restrictions, or permission issues, proceed to Path B.

### Path B: Docker Container Execution (Fallback)

When native installation is not possible, use a Playwright Docker image for headless browser testing.

#### Option 1: Pre-built Playwright Docker Image

```bash
# Pull the official Playwright Docker image
docker pull mcr.microsoft.com/playwright:v1.50.0-jammy

# Run tests inside container (mount workspace, share results)
docker run --rm \
  -v $(pwd):/work \
  -w /work \
  mcr.microsoft.com/playwright:v1.50.0-jammy \
  npx playwright test
```

#### Option 2: Custom Dockerfile for Persistent Setup

If tests run frequently, create a reusable Docker setup:

```dockerfile
FROM mcr.microsoft.com/playwright:v1.50.0-jammy

WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production && npm install -D @playwright/test
COPY . .
```

Build and run:

```bash
docker build -t playwright-tests .
docker run --rm \
  -v $(pwd)/test-results:/app/test-results \
  -v $(pwd)/playwright-report:/app/playwright-report \
  playwright-tests npx playwright test
```

#### Option 3: Docker Compose for App + Tests

When the application under test also runs in Docker, orchestrate both:

```yaml
services:
  app:
    build: ./path-to-app
    ports:
      - "3000:3000"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000"]
      interval: 5s
      timeout: 3s
      retries: 10

  e2e-tests:
    image: mcr.microsoft.com/playwright:v1.50.0-jammy
    working_dir: /app
    volumes:
      - .:/app
      - /app/node_modules
    environment:
      - PLAYWRIGHT_TEST_BASE_URL=http://app:3000
    depends_on:
      app:
        condition: service_healthy
    command: npx playwright test
```

## Phase 3: Test Configuration

### Screenshot Capture Setup

Configure Playwright to capture screenshots for visual verification. Edit or create `playwright.config.ts`:

```typescript
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  reporter: [['html'], ['list']],
  timeout: 30_000,
  use: {
    baseURL: process.env.APP_URL || 'http://localhost:3000',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
  projects: [
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
    },
  ],
});
```

### Per-Test Screenshots

For tests requiring visual verification at multiple steps, add explicit screenshot calls in test code:

```typescript
test('user can complete checkout flow', async ({ page }) => {
  await page.goto('/checkout');

  // Screenshot key states for agent review
  await page.screenshot({ path: 'screenshots/checkout-page.png' });

  await page.fill('[name="email"]', 'test@example.com');
  await page.click('button[type="submit"]');

  await page.waitForURL('/confirmation');
  await page.screenshot({ path: 'screenshots/confirmation-page.png' });

  expect(page.url()).toContain('/confirmation');
});
```

## Phase 4: Running Tests

### Native Execution

```bash
# Run all tests
npx playwright test

# Run specific file or tag
npx playwright test e2e/login.spec.ts
npx playwright test --grep @smoke

# Run with UI mode for debugging (native only)
npx playwright test --ui

# Generate HTML report
npx playwright show-report
```

### Docker Execution

```bash
# All tests

# Specific file
docker run --rm -v $(pwd):/work -w /work mcr.microsoft.com/playwright:v1.50.0-jammy npx playwright test e2e/login.spec.ts

docker run --rm \

  -w /work \

```

## Phase 5: Visual Verification Workflow

After tests complete, the agent must review screenshots to verify UI correctness beyond automated assertions.

### Step 1: Collect Artifacts

```bash
# List all captured screenshots
ls -la test-results/*/screenshots/ 2>/dev/null || ls -la screenshots/ 2>/dev/null

# List HTML report location
ls -la playwright-report/index.html 2>/dev/null
```

### Step 2: Agent Visual Review

Read each screenshot file using the Read tool. For each screenshot, verify:

1. **Page loaded correctly** — no blank screens, loading spinners stuck, or broken layouts
2. **Expected elements visible** — buttons, forms, content match what the test describes
3. **No error messages** — toasts, banners, or inline errors that shouldn't appear
4. **Correct state transitions** — navigation between pages shows expected content
5. **Responsive rendering** — no overflow, clipped text, or misaligned elements

### Step 3: Document Visual Findings

For each reviewed screenshot, record findings in the QA report:

```markdown
#### Screenshot Review: {test-name}

| Screenshot | Status | Notes |
|------------|--------|-------|
| `checkout-page.png` | Pass | All form fields rendered correctly |
| `confirmation-page.png` | Fail | Order summary shows wrong total; see bug report below |
```

## Writing New Playwright Tests

When no tests exist for a feature, create them following this structure:

### Directory Layout

```
project-root/
  e2e/
    playwright.config.ts
    fixtures/
      test-users.ts
    helpers/
      auth-helper.ts
    pages/
      login-page.ts
    specs/
      login.spec.ts
      checkout.spec.ts
  screenshots/              # Created at runtime
  test-results/             # Created by Playwright on failure
```

### Page Object Pattern (Recommended)

```typescript
// e2e/pages/login-page.ts
export class LoginPage {
  constructor(private page: Page) {}

  goto() { return this.page.goto('/login'); }
  fillEmail(email: string) { return this.page.fill('[name="email"]', email); }
  fillPassword(password: string) { return this.page.fill('[name="password"]', password); }
  submit() { return this.page.click('button[type="submit"]'); }
  getErrorMessage() { return this.page.locator('.error-message'); }

  async login(email: string, password: string) {
    await this.goto();
    await this.fillEmail(email);
    await this.fillPassword(password);
    await this.submit();
  }
}
```

### Test with Screenshots

```typescript
// e2e/specs/login.spec.ts
import { test, expect } from '@playwright/test';
import { LoginPage } from '../pages/login-page';

test.describe('Login', () => {
  test('successful login redirects to dashboard', async ({ page }) => {
    const loginPage = new LoginPage(page);
    await loginPage.login('user@example.com', 'password123');

    await page.screenshot({ path: 'screenshots/login-redirect.png' });
    expect(page.url()).toContain('/dashboard');
  });

  test('invalid credentials show error message', async ({ page }) => {
    const loginPage = new LoginPage(page);
    await loginPage.login('user@example.com', 'wrongpassword');

    await page.screenshot({ path: 'screenshots/login-error.png' });
    await expect(loginPage.getErrorMessage()).toBeVisible();
  });
});
```

## Error Handling

| Error | Cause | Resolution |
|-------|-------|-----------|
| Browser not found | Browsers not installed | Run `npx playwright install --with-deps chromium` or use Docker path |
| CANNOT_FIND_WORKSPACE | Docker volume mount issue | Verify `-v $(pwd):/work` resolves to correct absolute path |
| Connection refused | App not running at baseURL | Start the application first; verify with `curl {baseURL}` |
| Timeout exceeded | Element not appearing in time | Increase `timeout` in config; check for async loading states |
| Docker pull failed | Network / registry access | Check network connectivity; try alternative tag version |
| Missing system deps (native) | Linux libraries not installed | Use `--with-deps` flag or switch to Docker path |
